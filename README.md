# Dámeli Care

Чат поддержки покупателей на русском и казахском языках. Поиск по описаниям,
характеристикам и вопросам покупателей; ответы локально через **Ollama + Qwen2.5:7B**.
Ключ облачной языковой модели не нужен.

## Первый запуск чата

Установите [Ollama для Windows](https://ollama.com/download/windows).
Из корня проекта выполните:

```powershell
uv sync
if (!(Test-Path .env)) { Copy-Item .env.example .env }
.\scripts\start-local.ps1
```

Откройте <http://127.0.0.1:8000>. FastAPI обслуживает интерфейс и API вместе.
Индекс BM25 читается один раз при старте сервера; дождитесь
`Application startup complete`.

Скрипт запускает локальную Ollama при необходимости, проверяет наличие модели
и запускает FastAPI. Используется `qwen2.5:7b`.
Файлы модели хранятся в каталоге Ollama;
исходные данные и поисковый индекс остаются в `data/`.
Повторный запуск: `.\scripts\start-local.ps1`.
Если PowerShell запрещает скрипты, используйте обычные команды:

```powershell
ollama pull qwen2.5:7b
uv run uvicorn rmt_assignment3_project.api.api:app --host 127.0.0.1 --port 8000
```

Ollama должна быть запущена в фоне; иначе выполните `ollama serve` в отдельном терминале.
В `.env` задайте:

```dotenv
RAG_LLM_PROVIDER=ollama
RAG_LLM_MODEL=qwen2.5:7b
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_TIMEOUT_SECONDS=120
OLLAMA_NUM_CTX=8192
OLLAMA_NUM_PREDICT=192
OLLAMA_REPEAT_PENALTY=1.0
OLLAMA_REPEAT_LAST_N=128
OLLAMA_TEMPERATURE=0
OLLAMA_KEEP_ALIVE=10m
```

Контекст — 8192 токена, максимальный ответ — 192 токена. Штраф за повторения — 1.0
на последних 128 токенах. Для генерации используются до трёх записей, каждая не длиннее
2400 символов. Если товар выбран, записи других товаров исключаются из генерации.
Обрезка длинной записи может исключить нужный факт; полный текст остаётся в источниках.
Модель остаётся в памяти
10 минут после запроса. Первый ответ включает загрузку модели в память;
скорость и расход памяти зависят от компьютера. Качество казахского оценивается отдельно.
После изменения `.env` перезапустите API: `POST /reload` обновляет только индекс.
`/health` показывает настроенную модель, но не проверяет готовность Ollama;
скрипт запуска проверяет её отдельно.

Поиск работает на **BM25**, индекс находится в `data/rag_index/`. Он включает
описания, характеристики и вопросы с ответами продавца. Нейросеть для поиска
не загружается. Для пересборки после изменения данных:

```powershell
uv run python -m rmt_assignment3_project.rag.index --embedder bm25
```

Выберите товар в чате для поиска только по его карточке. Без выбранного товара
поиск идёт по всему ассортименту. Диалоги сохраняются в браузере; новый диалог
начинается с кнопки «Новый диалог». В каждом ответе можно раскрыть источники.
Вопросы отправляются отдельно: переписка отображает историю, но предыдущие
сообщения не передаются модели как контекст.

Если сервер защищён переменной `API_KEY`, укажите этот ключ в настройках
подключения (кнопка внизу левой панели). Он хранится в `sessionStorage` вкладки.
Ollama не требует ключа. Интернет нужен для первого скачивания модели и установки
зависимостей. Поиск BM25 и генерация скачанной моделью работают локально.

BM25 использует частоты слов, редкость термов и длину записи (`k1=1.5`, `b=0.75`).
Русские и английские слова приводятся к основам Snowball; Unicode-токенизация
сохраняет казахские символы. Казахские запросы расширяются русскими терминами
из словаря косметических характеристик. Это помогает искать объём, состав,
водостойкость и применение; полноценного автоматического перевода запросов нет.

Для казахских вопросов контекст выделяет соответствующие поля характеристик
или предложения описания. Простые подтверждённые факты (отсутствие отдушек,
парабенов и красителей, водостойкость, объём, частота применения и удаление SPF)
формулируются шаблонами на казахском без вызова LLM. Шаблоны зависят от значений
источника, а не от SKU или списка тестовых вопросов; неизвестные и составные
вопросы передаются модели. Остальные ответы генерирует Qwen с короткой английской
инструкцией и примерами казахских ответов. Повторы, XML-разметка источников
и ответы, оборванные лимитом токенов, возвращаются как ошибка генерации.
Языковую точность и соответствие источникам нужно оценивать отдельно;
качество произвольных ответов на казахском всё ещё ограничено моделью.

`RAG_MIN_SCORE=0`: учитываются только записи с положительной оценкой BM25.
Оценка не ограничена единицей и не является процентом уверенности. Бонус ответам
продавца сохранён, но не позволяет вернуть запись без совпадающих слов.
Выбор SKU и `--strict` продолжают ограничивать поиск выбранной карточкой.
При смене метода поиска старые оценки T1/T2/T5 нужно получить заново.

Старый векторный режим доступен только как опциональное сравнение:
`uv sync --extra embeddings`, затем сборка `--embedder st` в отдельный каталог.
Основная установка и запуск используют BM25.

Одиночный вопрос из терминала:

```powershell
uv run python -m rmt_assignment3_project.rag.ask "Как использовать скраб?" --item 5569571106 --strict --llm ollama
```

При 503 проверьте, запущена ли Ollama и загружена ли модель. При 504 проверьте
доступную память и `OLLAMA_TIMEOUT_SECONDS` (для чата рекомендуется не больше 120).
В ответах показывается фактическое имя модели.

API: <http://127.0.0.1:8000/docs>.

## Оценка T1–T5

При запущенном сервере выполните во втором терминале:

```powershell
uv run python eval/run_eval.py answers --questions eval/questions_answerable.csv --runs 1 --pause 3
```

Ответы — `eval/results/groundedness_sheet.csv`. Лимит FastAPI 30 запросов в минуту
остаётся включённым; квот облачной генерации нет. После смены генератора T3/T5
выполняются заново. Предыдущие результаты архивируются отдельно.

Инструкции, независимые вопросы и зафиксированная версия сборки находятся в
[`eval/README.md`](eval/README.md). Признаки продавца исправлены и проверены
по исходным ответам Ozon; оба индекса содержат 34 записи с ответом продавца.
Тесты оценивают эту сборку. Для уже запущенного API перечитайте индекс через
`POST /reload` с ключом доступа или перезапустите сервер перед проверками.

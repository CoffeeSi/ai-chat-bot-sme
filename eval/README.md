## Исправление продавца перед оценкой

Старый код определял продавца по префиксам ООО/ИП/ТОО в имени. Все 34 автора
в данных — DAMELI, поэтому этот метод выдавал ноль.

Теперь парсер сохраняет `answers.is_seller`, `seller_flag_source` и аватар автора.
Используется явная роль API, а при её отсутствии — совпадение **имени и аватара**
с профилем магазина `sellerTransparency`. Одно имя или юридический префикс не
считаются доказательством. Неизвестная роль остаётся NULL.

Существующие 34 ответа проверены по `answerUuid` в свежих ответах Ozon. Доказательства
и отчёт миграции находятся в `data/seller_audit/`; резервная копия базы и JSON —
в `data/backups/`. Результат: 34 ответа продавца, 0 неизвестных ролей.

Повторить восстановление по сохранённым ответам:

```powershell
uv run python -m rmt_assignment3_project.parsers.repair_seller_flags --offline
```

Метаданные основного индекса пересобраны командой `rag.index --reuse-vectors`.
В этом режиме код сначала проверяет совпадение модели, всех ID, текстов и порядка
записей. Численные векторы остаются прежними: роль влияет на prior и промпт,
но не входит в текст эмбеддинга. Если тексты изменились, команда требует обычную
пересборку. Хеш-индекс построен заново командой:

```powershell
uv run python -m rmt_assignment3_project.rag.index --embedder hash --out rag_index_hash
```

Оба индекса: 671 запись, 34 записи с ответом продавца. Приоритеты: 32 × +0.03,
1 × +0.04 (дополнительный бонус за лучший ответ), 1 × −0.05 (спорный ответ).

## Воспроизводимость

`run_manifest.json` содержит SHA-256 исходников, вопросов, базы и обоих индексов,
а также несекретные настройки модели и поиска. `run_eval.py` проверяет манифест
перед запуском и останавливается, если сборка изменилась. Значения ключей туда не входят.
Для новой сборки сначала архивируйте старые `results/` и манифест, затем запускайте
`uv run python eval/freeze.py`. Не смешивайте результаты разных сборок.

Регрессионные проверки роли, миграции схемы, ранжирования и промпта:

```powershell
uv run python -m unittest discover -s eval -p test_seller_flags.py -v
```

## Запуск

```powershell
uv run python eval/run_eval.py retrieval
uv run uvicorn rmt_assignment3_project.api.api:app --host 127.0.0.1 --port 8002
uv run python eval/run_eval.py api --base http://127.0.0.1:8002
uv run python eval/run_eval.py answers --base http://127.0.0.1:8002
```

Для API-тестов сервер должен быть запущен **после** пересборки индекса.
Ключ читается из `.env`; не передавайте его аргументом команды. Генерации T3 и T5
обращаются к настроенной Gemini. T1/T2 и запросы T4 с `min_score=1.0` не вызывают LLM.
В статистику задержек включаются только успешные HTTP 200, ошибки учитываются отдельно.

## Что заполняют люди

- `results/retrieval_results.csv`: колонка `record_relevant` (0/1). Полные тексты
  найденных источников доступны в `results/retrieval_sources.json`.
- После разметки: `uv run python eval/run_eval.py retrieval-summary`.
- `results/groundedness_sheet.csv`: независимые оценки двух людей, колонки `rater1`
  и `rater2`, значения 0/1/2. Ошибки сервиса не являются ответами модели и должны
  учитываться как ошибки, а не как «нет данных».
- После обеих оценок: `uv run python eval/run_eval.py ratings`.

В этих колонках нет автоматических или выдуманных оценок. Скрипт T5 сохраняет
промежуточный CSV после каждого запроса. Для переноса в отчёт используйте только
свои итоговые артефакты `results/`, не результаты чужой тестовой сборки.
